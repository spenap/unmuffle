  <action>
Thread `languageCode` through every layer of the call chain. All changes are additive — existing callers without the parameter (like `SmokeTestActivity`) continue to work via default parameter values.

**1. whisper_jni.cpp** — Add `jstring languageCode` as the LAST parameter of `fullTranscribe`:
```cpp
JNIEXPORT void JNICALL
Java_com_simonpena_transchat_WhisperLib_00024Companion_fullTranscribe(
        JNIEnv *env, jobject /* thiz */, jlong contextPtr, jint numThreads,
        jfloatArray audioData, jstring languageCode) {
```
Inside the function:
- After setting up `params`, acquire the language string: `const char* lang = env->GetStringUTFChars(languageCode, nullptr);`
- Replace `params.language = "auto";` with `params.language = lang;`
- Update the LOGI to include lang: `LOGI("Starting transcription with %d threads on %d samples, lang=%s", numThreads, (int)audioDataLength, lang);`
- AFTER `whisper_full()` returns (NOT before), release: `env->ReleaseStringUTFChars(languageCode, lang);`
- The release MUST come after `whisper_full()` because `params.language` stores the pointer directly during inference.

**2. WhisperLib.kt** — Add `languageCode: String` to `fullTranscribe` external fun:
```kotlin
external fun fullTranscribe(contextPtr: Long, numThreads: Int, audioData: FloatArray, languageCode: String)
```

**3. WhisperLib.kt (WhisperContext class)** — Add `languageCode: String = "auto"` to `transcribeData()`:
```kotlin
suspend fun transcribeData(
    data: FloatArray,
    languageCode: String = "auto",
    onProgress: (Int) -> Unit = {}
): String
```
Inside, update the call to: `WhisperLib.fullTranscribe(ptr, WhisperCpuConfig.preferredThreadCount, data, languageCode)`

**4. WhisperEngine.kt** — Add `languageCode: String = "auto"` to `transcribe()`:
```kotlin
suspend fun transcribe(audioData: FloatArray, languageCode: String = "auto", onProgress: (Int) -> Unit = {}): String
```
Inside, update the call to: `ctx.transcribeData(audioData, languageCode, onProgress)`
Update the Log.i to include languageCode: `"Starting transcription of ${audioData.size} samples (${audioData.size / 16000.0f}s) lang=$languageCode"`

**5. TranscriptionViewModel.kt** — Read language from SettingsRepository and pass through:
- Add `languageCode: String = SettingsRepository.getLanguage(getApplication())` parameter to `startTranscription()`:
  ```kotlin
  fun startTranscription(audioPath: String, languageCode: String = SettingsRepository.getLanguage(getApplication())) {
  ```
  This reads the saved language preference as the default value. If no preference is stored, SettingsRepository returns `"auto"`. Callers can still override by passing an explicit languageCode (Phase 13 language dialog will do this).
- Inside, where `engine.transcribe(pcm)` is called, change to: `engine.transcribe(pcm, languageCode)`
- Add import for `SettingsRepository`.

CRITICAL: The parameter addition in WhisperLib.kt external fun and whisper_jni.cpp MUST match exactly. JNI does not validate parameter types at compile time — a mismatch causes `UnsatisfiedLinkError` at runtime (Pitfall 2 from research).

Do NOT change TranscriptionActivity.kt — it still calls `viewModel.startTranscription(audioFilePath)` with no language argument, which triggers the default value reading from SettingsRepository. Phase 13 will add the language dialog that passes an explicit language.
