  <action>
Create `AudioCopier.kt` in the `com.simonpena.transchat` package. This is a stateless utility object that handles the synchronous content URI to cache file copy.

**Class structure:**
```kotlin
object AudioCopier {
    const val MAX_FILE_SIZE_BYTES = 25L * 1024 * 1024  // 25 MB

    sealed class CopyResult {
        data class Success(val file: File) : CopyResult()
        data class TooLarge(val sizeBytes: Long) : CopyResult()
        data object NoContent : CopyResult()
        data object CopyFailed : CopyResult()
    }

    fun queryFileSize(contentResolver: ContentResolver, uri: Uri): Long
    fun copyToCache(context: Context, uri: Uri): CopyResult
}
```

**queryFileSize implementation:**
- Use `contentResolver.query(uri, arrayOf(OpenableColumns.SIZE), null, null, null)`
- Return the SIZE column value if present and non-null
- Return -1L if cursor is null, empty, or SIZE column missing (per Pitfall 6 in research)

**copyToCache implementation:**
1. Query file size first. If size > MAX_FILE_SIZE_BYTES, return `TooLarge(sizeBytes)`.
2. Create `File(context.cacheDir, "audio")` directory with `mkdirs()`.
3. Generate destination file: `File(audioDir, "share_${System.currentTimeMillis()}.bin")`
4. Open `contentResolver.openInputStream(uri)` -- if null, return `NoContent`.
5. Use `input.copyTo(output)` with default 8KB buffer (NOT `readBytes()` which loads entire file into memory).
6. If `bytesCopied == 0L`, delete the empty file and return `NoContent`.
7. If size query returned -1L (unknown), check `bytesCopied > MAX_FILE_SIZE_BYTES` after copy. If exceeded, delete the partial file and return `TooLarge(bytesCopied)`.
8. Wrap in try-catch: on any Exception, delete the destination file and return `CopyFailed`.
9. On success, return `Success(destFile)`.

**Important:** This runs synchronously on the main thread. A 25MB copy takes ~50-200ms, well within the 5s ANR threshold. Do NOT use coroutines or Dispatchers.IO.

**Part A: Create ShareReceiverActivity.kt**

Create `ShareReceiverActivity.kt` in `com.simonpena.transchat`. This is a transparent activity (no layout, no setContentView) that receives audio shares.

**onCreate flow (all synchronous before any coroutine):**

1. `super.onCreate(savedInstanceState)` -- no setContentView (transparent theme).
2. Guard: if `intent?.action != Intent.ACTION_SEND`, show toast "Could not process this file." and `finish()`.
3. Model check: if `!ModelManager.isModelPresentFast(this)`, show toast "Model needed", start DownloadActivity, `finish()`, return.
4. Extract URI: `@Suppress("DEPRECATION") intent.getParcelableExtra<Uri>(Intent.EXTRA_STREAM)`. If null, toast "Could not process this file." and `finish()`.
5. Call `AudioCopier.copyToCache(this, uri)` synchronously.
6. Handle CopyResult:
   - `TooLarge` -> toast "File too large (25MB max). TransChat works best with voice messages." and `finish()`
   - `NoContent` -> toast "Could not process this file." and `finish()`
   - `CopyFailed` -> toast "Could not process this file." and `finish()`
   - `Success(file)` -> store `file` in a `private var cachedAudioFile: File? = null` property, then launch decode coroutine

7. For now (Phase 2, Plan 01), the decode coroutine is a placeholder that logs the cached file path and size:
```kotlin
lifecycleScope.launch {
    // Phase 2 Plan 02 will replace this with AudioDecoder pipeline
    android.util.Log.i("ShareReceiver", "Audio cached: ${cachedAudioFile!!.absolutePath} (${cachedAudioFile!!.length()} bytes)")
    Toast.makeText(this@ShareReceiverActivity, "Audio received (${cachedAudioFile!!.length() / 1024}KB)", Toast.LENGTH_SHORT).show()
    finish()
}
```

**onDestroy cleanup:**
Override `onDestroy()`. If `cachedAudioFile != null`, delete it. Log the deletion. Call `super.onDestroy()`.

**Part B: Update AndroidManifest.xml**

Add ShareReceiverActivity declaration inside the `<application>` block, before the SmokeTestActivity entry. Use TWO separate intent-filter elements per the research (not one filter with multiple data elements):

```xml
<!-- Share target: transparent, no UI, receives audio shares -->
<activity
    android:name=".ShareReceiverActivity"
    android:exported="true"
    android:label="TransChat"
    android:theme="@android:style/Theme.Translucent.NoTitleBar">

    <!-- Intent filter 1: standard audio MIME types (WhatsApp, most apps) -->
    <intent-filter>
        <action android:name="android.intent.action.SEND" />
        <category android:name="android.intent.category.DEFAULT" />
        <data android:mimeType="audio/*" />
    </intent-filter>

    <!-- Intent filter 2: octet-stream (Telegram voice messages) -->
    <intent-filter>
        <action android:name="android.intent.action.SEND" />
        <category android:name="android.intent.category.DEFAULT" />
        <data android:mimeType="application/octet-stream" />
    </intent-filter>
</activity>
```

Key manifest details:
- `exported="true"` required for other apps to send to this activity
- `label="TransChat"` controls share sheet display text (just "TransChat", no subtitle per user decision)
- `Theme.Translucent.NoTitleBar` -- no visible window
- Two separate `<intent-filter>` elements, NOT one filter with two `<data>` elements
